# i18n — English / German Bilingual Support

**Date:** 2026-03-15
**Status:** Approved

---

## Goal

Add full German translation to the Web Dev Visual Guide. English remains the default. Users switch language via a compact toggle in the Navbar; preference persists in `localStorage` automatically via i18next-browser-languagedetector. Scope: all UI text **and** all learning content (topic explanations, categories, resources, references). URL routes stay English.

---

## Packages

```
i18next
react-i18next
i18next-browser-languagedetector
```

## Initialization Lifecycle

All namespace JSON files are **statically imported** — `i18n.init()` is synchronous. The init is a side-effect import in `main.tsx` before `createRoot`:

```ts
// src/i18n/index.ts — runs synchronously, exports initialized instance
i18n.use(LanguageDetector).use(initReactI18next).init({ ... })
i18n.on('languageChanged', lng => { document.documentElement.lang = lng })
document.documentElement.lang = i18n.language
export default i18n

// src/main.tsx
import './i18n/index'   // side-effect: runs before render
```

No `<Suspense>` boundary required. No async flicker. Uses localStorage key `wdvg-lang` (separate from Zustand's `wdvg-settings`).

## Data Hooks (`src/i18n/hooks.ts`)

All hooks are React hooks (call `useTranslation()` internally, valid only in components).

### `useCategories(): Category[]`
Returns `CATEGORIES` with `title`, `description`, `cardLabel` replaced via `t('[id].title', { ns: 'categories' })`.

### `useTopicLabels(): Record<string, string>`
Returns the `TOPIC_LABELS` record with values from `t('topicLabels.[id]', { ns: 'categories' })`.

### `useCategoryGroups()`
Returns `CATEGORY_GROUPS` with `label` replaced via `t('groups.[group.key]', { ns: 'home' })`. Keys used: `markup-style`, `programmierung`, `frameworks-web`, `tools`.

### `useTechMeta()`
Returns `TECH_SECTION_META` with `title`/`subtitle` replaced via `t('techMeta.[tech].title', { ns: 'categories' })`.

### `useTopic(id: string): Topic | undefined`

Return type: `Topic` (identical to existing type — no new type needed).

Strategy: translate only the prose fields of the explanation `Section` steps and cheatSheet; all other `Topic` fields are passed through unchanged from the static data.

```ts
function useTopic(id: string): Topic | undefined {
  const ns = topicsNamespaceFor(id)  // 'topics-html' | 'topics-css' | ...
  const { t } = useTranslation(ns)
  const base = TOPICS.find(t => t.id === id)
  if (!base) return undefined

  const tx = t(id, { returnObjects: true }) as TopicTranslation

  return {
    ...base,
    title: tx.title,
    description: tx.description,
    sections: base.sections.map(section => {
      if (section.type !== 'explanation') return section
      return {
        ...section,
        steps: section.steps.map((step, i) => ({
          ...step,                          // keeps animationStep, icon, codeExample, language
          heading: tx.steps[i]?.heading ?? step.heading,
          text:    tx.steps[i]?.text    ?? step.text,
        })),
      }
    }),
    cheatSheet: base.cheatSheet && tx.cheatSheet
      ? mergeCheatSheet(base.cheatSheet, tx.cheatSheet)
      : base.cheatSheet,
  }
}
```

`mergeCheatSheet` replaces prose fields (`label`, `note`, `title`, `whenToUse`, `commonMistakes`) while keeping `code` and `language` from the base.

### `useTopics(): Topic[]`
Returns all topics with translated prose. Return type: `Topic[]`. Used by `useSearch` and `CategoryPage`.

### `useResourceGroups(): ResourceGroup[]`
Returns `RESOURCE_GROUPS` with `label` and each resource's `name`/`description` replaced from the `resources` namespace. `icon: ReactNode` is passed through unchanged from static data.

## `useSearch` Update

`useSearch.ts` currently imports `TOPICS` directly. After i18n, it calls `useTopics()` to receive the translated `Topic[]`. The existing filter logic (`topic.title`, `topic.description`) is unchanged — it now operates on translated strings, so German users can search in German.

## Language Switcher (Navbar)

`LanguageSwitcher` component: two `<button>` elements (`EN` / `DE`), ~70px total width, placed to the left of the theme toggle. `i18n.changeLanguage(lang)` is the only call needed — LanguageDetector writes to `localStorage` automatically.

## Implementation Order

1. `npm install i18next react-i18next i18next-browser-languagedetector`
2. Create `src/i18n/index.ts` + `src/i18n/i18next.d.ts`
3. Create all EN JSON files (extract current English strings — this defines the schema)
4. Create all DE JSON files (full German translations)
5. Wire `import './i18n/index'` in `main.tsx`
6. Create `src/i18n/hooks.ts`
7. Add `LanguageSwitcher` to `Navbar.tsx`
8. Update UI components (`common`, `home`, `topic`, `resources`, `reference` namespaces)
9. Update data-consuming components to use hooks
10. Update `useSearch.ts` to use `useTopics()`
11. `npx tsc --noEmit`

## Out of Scope

- URL localization
- RTL support
- More than 2 languages
- `Resource.icon` (ReactNode — JSX, stays in source)
- Code snippets, playground starter code, `cheatSheet.code` fields, SVG labels
